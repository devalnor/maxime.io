# September 2026 review

This is the first-pass review of maxime.io. It separates safe quick wins from
changes that need a positioning or architecture decision.

## Executive summary

The site still has a distinctive visual identity and a clear personal voice,
but its technology and content both read as a 2020 portfolio. The production
build succeeds on Node.js 22, yet the dependency tree contains 21 known
vulnerabilities: 1 critical, 15 high, 4 moderate and 1 low.

The right next move is a focused modernization, not a series of blind package
bumps. Next.js 12, React 17, styled-components 5 and Framer Motion 5 all sit
several major versions behind their current releases. The older responsive,
font-loading, scrolling, swipe and obfuscation packages also make a major
framework upgrade harder than the size of this one-page site should warrant.

## What still works

- `npm ci`, `npm run lint` and `npm run build` all succeed on Node.js 22.13.1.
- The page is statically generated and the local server returns HTTP 200.
- The portrait, dark navy palette and direct opening statement provide a
  recognizable first screen.
- The live analytics endpoint and production site both respond successfully.

## Technical findings

### High priority

1. **Unsupported application foundation.** The project uses Next.js 12.3.4 and
   React 17.0.2. The npm registry reports Next.js 16.3.5 and React 19.3.0 as the
   current releases on 14 September 2026.
2. **Known security debt.** `npm audit` reports 21 vulnerabilities. The direct
   Next.js dependency accounts for the critical advisory and several high and
   moderate advisories. A non-breaking patch cannot clear the full set.
3. **No automated tests or CI.** The only reliable checks are lint and a full
   production build. Interactive behavior has no regression coverage.
4. **Legacy client-side machinery.** Fresnel, react-obfuscate, swipe-js-iso and
   lodash.isequal add code and migration
   constraints to a single-page site. Most can be replaced with browser or
   framework primitives.

### Medium priority

1. The custom Babel configuration disables Next.js's SWC compiler.
2. The ESLint setup does not extend the Next.js plugin and is on ESLint 7.
3. The initial JavaScript payload is about 153 kB, high for a mostly static
   professional page.
4. `now.json` predates current Vercel configuration conventions.
5. PNG logos and photos lack explicit dimensions and modern image delivery.

## Design and accessibility findings

The first screen communicates “experienced digital generalist.” The first
three visual anchors are the portrait, the headline and the blue contact CTA.
That hierarchy works. The main issue is that the rest of the page feels like a
technology inventory rather than evidence of current impact.

- The technology logo wall foregrounds tools, including Adobe XD, InVision and
  Heroku, that may no longer represent the intended positioning.
- Section titles are styled `div` elements and the customer categories jump
  from the single `h1` directly to `h3`, weakening document structure.
- Most sections start at zero opacity and only appear after an intersection
  observer fires. Reduced-motion preferences are not handled.
- Mobile composition is very tall, with large empty visual intervals and small
  secondary text.
- The LinkedIn icon in the navigation measures 66 × 42 px, just below the
  recommended 44 px minimum touch height.
- The customer list is long and undifferentiated. Two or three short case
  studies would prove expertise better than a directory of names.

## Content decisions to make next

These cannot be guessed safely from the repository:

1. What title should replace “Technology Expert & Digital Consultant” in 2026?
2. Which audience is primary: clients, employers, partners or speaking/events?
3. Which three recent outcomes can be stated with a number, scope or result?
4. Which client names can still be displayed, and which five matter most?
5. Which capabilities should lead now: product, engineering, AI, design,
   strategy, leadership or another mix?
6. Should the page remain English-only, become French-first or support both?
7. Is `maxime@macoal.com` still the preferred public contact address?

## Quick wins completed on `sept-2026`

- Removed the React DOM-prop warning from the navigation.
- Replaced a clickable `div` with a real button and named every icon-only link.
- Restored semantic section headings and a 44 px navigation touch target.
- Improved body copy legibility by removing global negative tracking.
- Fixed the reversed accessible name generated by the obfuscated email link.
- Fixed the broken Montreal Bold font URL and enabled `font-display: swap`.
- Removed the blocking font-loading screen.
- Anchored the navigation CTA to the contact section and removed react-scroll.
- Refreshed grammar, labels, metadata, canonical URL, sitemap date and copyright.
- Removed dead imports and an expired analytics branch.
- Added a documented lint command and current local setup instructions.

## Recommended next phase

Choose the page's job and rewrite the content structure first. Then rebuild the
single page on a current foundation, preserving the portrait-led visual identity
while replacing the logo inventory with proof: a concise positioning statement,
three capabilities, two or three outcomes, selected references and one contact
action. Make the migration responsible for clearing the audit findings, adding
smoke tests and reducing the JavaScript payload.
